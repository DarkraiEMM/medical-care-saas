# 绩效积分第一版需求

## 范围

第一版把客观工作量与绩效计算分开。系统根据审核通过的服务任务、确认的销售记录和门店发布的积分方案自动生成月度绩效单；机构人员只负责核对、说明调整和确认，不手工逐项计算。

不包含工资发放、考勤工资、税务计算、劳动关系认定或自动罚款。

## 用户故事

1. 机构负责人希望设置本机构的积分规则，并指定生效日期。
2. 主管希望查看员工每日及月度工作量，但不把未审核任务当作完成。
3. 门店希望把员工促成并经确认的养老产品销售计入积分。
4. 机构负责人希望自动计算月度绩效单，并在有依据时添加可审计调整。
5. 员工和管理人员希望历史绩效使用当时规则，不因后来改规则而变化。
6. 机构负责人希望从平台推荐方案开始，像编辑多维表一样逐行调整指标和算法，而不是从空白规则开始。

## 验收标准

- 当机构查看工作量时，系统应分别展示参与、审核通过、负责人完成、协作完成、涉及退回和服务天数。
- 当机构发布新积分方案时，系统应创建新版本并保存生效日期，不覆盖旧版本。
- 当系统计算某月绩效时，应选择该月适用的已发布方案版本。
- 当任务未审核通过时，系统不得将其计入完成任务积分。
- 当销售记录未确认或已取消时，系统不得将其计入销售积分。
- 当同一服务任务有多人参与时，系统应分别按负责人和协作规则计分，但不得重复计算机构服务收入。
- 当管理人员添加绩效调整时，系统应要求填写原因并记录操作人、时间和分值。
- 当绩效单已确认时，系统应阻止重新计算和修改；如需纠正，应另建更正版本。
- 当规则被修改后，已生成绩效单应继续保留原方案版本和逐项计算明细。
- 当机构选择推荐方案时，系统应复制推荐规则形成机构草稿，机构可调整启用状态和每单位积分后再发布。
- 当机构配置计算规则时，系统应只允许引用已登记的可信指标来源，不得执行任意脚本或未知公式。
