# 医养照护 SaaS 第一阶段实施任务

> 状态：已获准实施
> 实施原则：先使用模拟数据打通主链路，不创建生产云资源，不处理真实老人资料。

## 1. 第一批：工程与数据底座

- [x] T001 建立 TypeScript 单仓库，统一格式化、静态检查、测试和构建命令。
- [x] T002 建立机构 Web、平台 Web、工作人员小程序和 API 的独立应用目录。
- [x] T003 建立共享业务类型、权限定义、配置读取和 API 契约包。
- [ ] T004 建立 MySQL/Prisma 初始模型及迁移，所有业务表包含 `tenantId` 和必要复合索引。
- [ ] T005 建立模拟数据种子：两个机构、多个部门、不同角色，用于验证租户隔离。
- [x] T006 建立环境变量样例；禁止提交密钥、真实手机号、OpenID 和生产连接串。

## 2. 第二批：身份、租户与权限

- [ ] T101 实现服务端身份上下文，不信任客户端传入的 `tenantId`。
- [ ] T102 实现机构管理员、部门主管、一线人员、核销人员和平台运维角色。
- [ ] T103 支持一名员工属于多个部门，并按部门范围合并权限。
- [ ] T104 实现离职停用、历史记录保留和操作主体快照。
- [ ] T105 实现平台人员默认无权查看机构正文，预留四小时临时支持授权模型。
- [ ] T106 自动化验证 A 机构无法读取、修改、搜索或导出 B 机构数据。

## 3. 第三批：首条业务闭环

- [ ] T201 老人档案：基础资料、照护注意事项、唯一主联系人及授权依据引用。
- [ ] T202 服务目录：平台默认项、机构启停/排序、自定义项和不可变版本。
- [ ] T203 月度服务周期：自然月、合同关联、自费/消费券金额和至少四条记录规则。
- [ ] T204 服务记录：一名或多名参与者、具体服务子项、日志、时间和前中后三阶段。
- [ ] T205 多人协作：允许团队共享材料，但每名参与者必须独立确认参与事实。
- [ ] T206 健康指标：血压、血糖、心率、体温的结构化数值、单位和测量情境。
- [ ] T207 影像元数据：原件与证据副本分离、哈希、上传状态和可选拍摄理由。
- [ ] T208 审核纠错：提交、退回、补正、重新提交；原记录不覆盖并保留版本历史。
- [ ] T209 月度材料包：周期汇总、明细、签字/确认、证据清单、哈希和核销台账。
- [ ] T210 民政通人工报送回填：操作人、时间、受理编号、结果和退回原因；不保存登录凭据。

## 4. 第四批：首轮可操作界面

- [ ] T301 机构 Web 登录壳、导航、老人列表、服务周期详情、审核和导出入口。
- [ ] T302 小程序登录绑定壳、任务列表、服务详情和前中后三阶段记录页。
- [ ] T303 使用模拟上传适配器演示图片/视频流程，生产对象存储接入后置。
- [ ] T304 提供模拟机构、老人、员工和月度记录，避免任何真实隐私数据进入开发环境。
- [ ] T305 加入隐私说明、账号注销/停用说明和自然人体验版边界提示。

## 5. 验收与发布闸门

- [x] T401 静态检查、单元测试、权限测试和全部应用构建通过。
- [ ] T402 人工走查一条“建档—服务周期—四次服务—审核—材料包”链路。
- [ ] T403 小程序在不同手机上验证拍照、1080P60 视频、弱网和定位拒绝场景。
- [ ] T404 生产前确认国内经营主体、隐私文本、处理协议、云账号归属和登录供应商配置。
- [ ] T405 生产前确认 MySQL 实际回档能力、对象存储备份和恢复演练方案。
- [ ] T406 功能代码通过 PR 审查后合并；生产部署另行人工批准。

## 6. 本次开发批次的完成定义

本分支先完成 T001—T006，并实现可测试的 T101、T106、T201—T206 核心领域模型；随后提供 Web 与小程序的第一条可操作主链路。对象存储、短信、电签、民政通和真实云资源不属于本批次自动开通范围。
