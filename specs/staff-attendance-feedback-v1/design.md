# 工作人员考勤、个人业绩、客户反馈与食品追溯移动采集设计

## 1. 设计原则

1. 考勤、服务阶段、客户反馈、食品追溯和绩效是不同业务对象，共用身份、文件和审计底座，但不共用状态。
2. 门店决定业务组件是否启用及字段选填/必填；平台只维护不可关闭的租户隔离、权限、审计、文件安全和正式地区合规规则。
3. 录音、签名和照片使用统一媒体适配器，业务表只保存引用及上下文，不把大文件写入 SQLite 字段。
4. 当前使用本地测试文件适配器；接口形状为未来对象存储保留稳定的文件编号、哈希、类型、大小、时长和访问权限。
5. 签名属于服务确认留痕，不命名为“可靠电子签名”或“电子签章”。

## 2. 产品界面设计

### 2.1 小程序信息架构

保留“任务、待修改、我的”三个主导航：

- 任务：首页顶部按权限显示“上下班考勤”和“食品追溯”快捷入口，下方仍是当天服务任务；
- 待修改：继续处理被退回的任务及客户反馈材料；
- 我的：工作身份、今日考勤、工作量与质量、绩效积分、隐私说明。

食品追溯不增加常驻底部导航。只有机构启用应用且员工拥有餐饮岗位权限时，任务首页才显示快捷入口。

### 2.2 客户反馈组件

服务表单设计器左栏新增“客户反馈”复合预设。拖入后在中栏展开真实预览，右栏配置：

- 组件整体：停用、选填或必填；
- 适用服务项目及适用阶段，默认位于服务后；
- 满意度、评价标签、文字意见、录音、手写签名、合照、拒绝或无法评价原因；
- 每个子项独立启用、选填/必填、标题和填写说明；
- 录音最长时长、照片数量及签名确认文案。

模板发布时生成不可变版本快照。任务继续引用派发时的反馈配置，后续配置不追溯改变历史任务。

### 2.3 现场采集交互

- 录音：按住或点击开始，明确显示计时、暂停/结束、试听、删除和重录；录音前显示用途说明；
- 签名：全宽横向画布，提供清除、重签和确认；同时选择确认人类型并填写关系说明；
- 拍照：使用小程序相机或相册选择，显示压缩前提示、上传进度、预览、删除和重传；
- 代录：文字输入区固定显示“由工作人员代为录入”，保存实际员工身份；
- 所有提交按钮显示加载、成功和失败反馈，失败后保留本地草稿及重试入口。

### 2.4 食品追溯移动表单

页面采用“先拍凭证、再补关键信息”的现场顺序：

1. 拍摄票据、许可证、检验报告、批次标签或供货凭证；
2. 选择凭证类型；
3. 填写或选择食材、供应商、批次、数量、流转类型和日期；
4. 可录制语音备注；
5. 保存草稿或提交机构复核。

食材、供应商和常用流转类型使用可搜索历史选项，仍允许授权人员新增；批次号支持扫码/手动输入的接口预留，首版先实现手动输入。

## 3. 数据模型

### 3.1 应用与规则

- `TenantApplicationSetting`：租户、应用编码、启用状态、套餐授权、维护状态；
- `AttendancePolicyVersion`：考勤时段、位置范围、容差、异常处理及生效时间；
- `CustomerFeedbackConfig`：模板版本中的复合组件配置和子字段规则；
- `FoodTraceTemplateVersion`：食品追溯字段、材料要求和复核规则。

### 3.2 业务记录

- `AttendanceRecord`：员工、日期、上班/下班时间、位置状态、异常、策略版本和审核状态；
- `TaskCustomerFeedback`：任务、版本、评价人类型、关系说明、满意度、标签、文字、代录员工、状态和配置快照；
- `BusinessMediaObject`：租户、业务类型、业务编号、媒体类型、文件名、MIME、大小、时长、哈希、上传人和测试标识；
- `FeedbackMediaLink`：反馈与录音、签名、照片之间的关联及用途；
- `FoodTraceRecord`：食材、供应商、批次、数量、流转类型、日期、责任人、状态和模板快照；
- `FoodTraceEvidenceLink`：流转记录与票据、证件、检验报告、批次标签、签收签字或语音备注之间的关联；
- 个人工作量和绩效继续读取现有任务、销售、积分方案和绩效单，不复制统计事实。

## 4. 状态与权限

### 4.1 客户反馈

`DRAFT -> CAPTURED -> PENDING_REVIEW -> ARCHIVED`，退回时进入 `RETURNED` 并建立新修订版本。员工只能编辑本人有权执行任务的草稿或指定待修改项；审核人员不能改写反馈正文。

### 4.2 食品追溯

`DRAFT -> SUBMITTED -> VERIFIED/RETURNED -> ARCHIVED`。餐饮工作人员新增和提交；食品安全负责人复核；机构管理员可以查询和导出，但不能静默覆盖已复核记录。

### 4.3 考勤

只有启用考勤应用的机构才能写入。员工只能提交本人记录；异常处理人只能确认或退回说明，不能伪造员工原始打卡时间和位置。

### 4.4 个人业绩

员工接口从身份中的员工编号确定查询范围，不接受任意员工编号。平台运营端不提供机构员工个人绩效正文接口。

## 5. API 设计

### 5.1 工作人员接口

- `GET /api/v1/staff/applications`：返回本人可见应用及入口状态；
- `GET /api/v1/staff/me/work-summary?month=`：本人工作量、质量和绩效摘要；
- `GET /api/v1/staff/attendance/today`：今日考勤及适用策略；
- `POST /api/v1/staff/attendance/check`：提交上班或下班考勤；
- `GET /api/v1/staff/tasks/:taskId/customer-feedback`：读取配置快照及当前反馈；
- `PUT /api/v1/staff/tasks/:taskId/customer-feedback`：保存反馈草稿；
- `POST /api/v1/staff/media`：上传图片、录音或签名测试文件；
- `GET/POST /api/v1/staff/food-trace-records`：查询及新增本人有权处理的流转记录；
- `PUT /api/v1/staff/food-trace-records/:id`：保存或提交记录。

### 5.2 机构接口

- 服务表单接口扩展客户反馈复合组件及模板版本；
- 应用设置接口控制考勤、食品追溯和客户反馈是否可用；
- 考勤策略接口发布版本并处理异常；
- 食品追溯接口复核、退回、查询和导出；
- 任务审核详情展示客户反馈、代录标记和受控媒体；
- 现有工作量与绩效接口增加员工本人摘要视图，不改变机构端规则计算。

## 6. 校验策略

1. 客户反馈只按任务所绑定的配置快照校验；组件停用或选填时不得阻止任务提交。
2. 每个媒体字段按类型、数量、大小、时长和测试标记校验。
3. 食品材料要求同时支持门店模板规则和未来正式地区规则；二者冲突时，正式地区硬规则优先。
4. 录音、签名和照片不能互相冒充；签字不能满足“正式票据或证件”类型要求。
5. 图片进入客户反馈或食品追溯后，不自动进入宣传素材。

## 7. 测试策略

- 仓储测试：租户隔离、版本快照、媒体关联、历史不可覆盖；
- 服务测试：门店选填/必填组合、应用启停、权限、反馈退回和食品复核；
- 小程序结构测试：新增页面路由、WXML 条件分支、媒体组件事件及技术错误不外露；
- 端到端测试：门店发布反馈模板、小程序采集、机构审核；餐饮人员拍凭证并提交、机构复核；员工考勤与个人绩效只看本人；
- 微信开发者工具回归：录音授权拒绝、相机权限拒绝、上传失败、断线重试和页面恢复。
