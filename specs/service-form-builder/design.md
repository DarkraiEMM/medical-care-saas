# 服务表单设计器技术设计

> 状态：已确认执行  
> 日期：2026-08-08  
> 对应需求：`requirements.md`

## 1. 模块边界

服务表单分为三个层次：

1. 系统事实字段由服务任务维护，包括老人、日期、时间、负责人、参与人员和审计信息；
2. 表单模板由机构配置，包含平台预设字段和机构自定义字段；
3. 服务答案由员工填写，并绑定执行时的模板版本和字段快照。

机构资质是独立模块。表单设计器只读取资质状态、触发门禁提示，不保存真实证照正文。

## 2. 核心数据结构

### 2.1 字段定义

`ServiceFormField` 包含：

- `id`：当前模板中的字段实例标识；
- `presetCode`：平台预设语义编码，自定义字段为空；
- `source`：`PRESET` 或 `TENANT_CUSTOM`；
- `type`：文字、数字、单选、多选、日期、时间或图片；
- `label`、`description`、`required`、`enabled`、`order`；
- `options`：单选、多选字段的版本化选项；
- `unit`：数字字段的可选单位；
- `qualificationCodes`：启用该字段所需的机构资质编码。

### 2.2 模板

`ServiceFormTemplate` 包含机构、模板标识、版本号、草稿/已发布状态和有序字段数组。本地验证版每个机构维护一个当前草稿和一个当前发布版本；生产数据库拆分为模板、版本、字段和选项表。

### 2.3 动态答案

服务记录新增 `answers`，每项包含字段实例标识、字段类型和结构化值。保存服务记录时同时保存模板标识、模板版本及字段快照。当前旧字段仅作为兼容导出数据，不再驱动页面。

### 2.4 资质记录

`OrganizationQualification` 包含资质编码、名称、文件标识、上传状态、审核状态、有效期、提交时间、审核人、审核时间和退回原因。演示租户可以使用演示材料走完整提交流程，但机构端无权修改审核结论。

## 3. API

- `GET /organization/service-form-workspace`：读取预设字段、通用组件、当前模板、人员和模拟资质；
- `POST /organization/service-form-template`：保存模板草稿；
- `POST /organization/service-form-template/publish`：校验必填配置和资质后发布新版本；
- `POST /organization/qualifications/:code/upload`：机构上传演示材料元数据；
- `POST /organization/qualifications/:code/submit`：机构提交平台审核；
- `GET /platform/qualifications`：平台查看各机构资质元数据与审核进度；
- `POST /platform/qualifications/:tenantId/:code/review`：平台通过或退回资质并记录审核轨迹；
- 服务记录创建接口增加模板版本和动态答案。

所有接口继续从身份上下文取得租户，不接受客户端指定其他租户。

## 4. 配置端

三栏设计器：

- 左栏：平台预设字段、通用组件；支持拖入和点击添加；
- 中栏：模板画布；支持选中、上移、下移和删除；
- 右栏：字段属性；支持标题、说明、必填性、单位和选项编辑；
- 加入受限字段时检查资质；不满足时打开门禁窗口；
- 保存草稿不会改变员工端，发布后员工端切换到新版本。

第一版使用原生 HTML 拖放并保留点击添加，以兼容不便拖动的设备和无障碍操作。

## 5. 员工表单

员工端先显示系统事实字段，再按发布模板顺序渲染动态字段。多选预设字段直接显示自身选项，不再显示“第一步/第二步”。字段校验由字段定义驱动；图片字段复用本地模拟图片和证据上传能力。

## 6. 兼容与迁移

当前本地 SQLite 配置 JSON 可以向新结构迁移：旧的前中后必填规则映射为四个预设文字字段，旧项目目录映射为预设多选字段。没有旧配置时直接使用测试门店默认模板。

当前原型服务记录继续生成兼容的 `log`、`stageNotes` 和 `serviceItemVersionIds`，同时保存动态答案；后续导出模块完成迁移后再删除兼容层。

## 7. 测试

- 仓储测试：模板与资质状态持久化、租户隔离；
- 服务测试：发布时资质门禁、必填字段校验；
- 浏览器测试：添加预设字段、自定义多选选项、保存/发布、员工端渲染和资质弹窗；
- 回归测试：老人档案、服务工单、负责人和图片证据继续工作。
